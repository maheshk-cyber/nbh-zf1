# Changelog

All notable changes to this port are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[semantic versioning](https://semver.org/spec/v2.0.0.html) on the patched
upstream version.

Measured status — violation counts, smoke results, work queue — lives in
[`PORTING.md`](PORTING.md), which is regenerated by `tools/port-status.sh`.
This file records *what changed and why*; that file records *where we are*.

---

## [Unreleased]
Baseline: Zend Framework 1.12.20 (upstream EOL), retargeted at PHP 8.1+ and
verified syntax-clean through PHP 8.5.

### Changed — repository history

- The porting commits carried a `Co-Authored-By: Claude Code` trailer. The
  maintainer is the sole author, so the trailer was removed from all five
  commits by rewriting local history. Trees are byte-identical before and after
  (`git diff` between the pre-rewrite branch and the result is empty), so no
  file content changed. The branch had never been pushed, so no remote history
  was affected.

### Fixed — fatal errors under PHP 8

- `Zend_Rest_Route::assemble()` gained the `$partial` parameter its parent
  `Zend_Controller_Router_Route_Module` declares. PHP 8 enforces this LSP rule
  at class-declaration time, so the class could not be loaded at all.
- `Zend_Soap_Client_Common::__doRequest()` now matches
  `SoapClient::__doRequest()`'s signature (`$oneWay = false`,
  `$uriParserClass = null`), which PHP 8 validates against the SPL class.
- `Zend_Service_Console_Command` appended its collected argument vector to the
  outgoing argument list under a *string* key (`$parameterValues['argv']`).
  PHP 7 ignored the key and passed the value positionally, so handlers that
  declared an extra trailing parameter received it. PHP 8 reads a string key as
  a **named** argument and refuses unknown names outright — every command that
  reached this path died with `Error: Unknown named parameter $argv`. The value
  is now appended positionally, restoring the PHP 7 behaviour exactly.
- `Zend_Service_WindowsAzure_Log_Writer_WindowsAzure` referenced three classes
  that do not exist in the tree — `Zend_Service_Log_Exception`,
  `Zend_Service_Log_Formatter_Interface` and
  `Zend_Service_Log_Writer_WindowsAzure`. Upstream escaped notice because the
  first two are only reached via `throw`; the third was a docblock typo. All
  three now point at their real `Zend_Log_*` counterparts.
- `Zend_Config_Yaml::_parseValue()` called `count()` on a string, which throws
  a `TypeError` on PHP 8. Now uses `strlen() - 1`.
- `Zend_XmlRpc_Value::_extractTypeAndValue()` could recurse forever on an empty
  `<value/>` element; the child-binding is now reset per attempt and falls
  through to the default string branch.

### Fixed — functions removed from PHP

- `each()` is gone from PHP 8. Replaced at four sites. `Zend_Config_Yaml` was
  the delicate one: it relied on `each()`'s internal array pointer together
  with `prev()` and recursion, so it now threads an explicit `$offset` cursor
  through `_decodeYaml()` instead of switching to `foreach`.
- `create_function()` (removed PHP 8) replaced with a closure in
  `Zend_Feed_Element::__get()`.
- `get_magic_quotes_gpc()` (removed PHP 5.4, but still called) — the guarded
  branch in `Zend_Tool_Project_Provider_DbAdapter` was dead code and is removed.
- `$php_errormsg` and the `track_errors` ini setting are gone from PHP 8, so 31
  sites across 11 files were silently reporting the *empty* error text. They now
  call `error_get_last()`, each guarded by `error_clear_last()` so a stale error
  from an earlier call is never mistaken for this one. This bites harder than it
  sounds: `error_get_last()` *does* capture `@`-suppressed errors on PHP 8 (the
  PHP 7 behaviour, where `@` cleared the buffer, was reversed), so the
  replacement preserves the original intent. Affected: `Zend_Feed`,
  `Zend_Feed_Abstract`, `Zend_Feed_Reader`, `Zend_Feed_Entry_Atom`,
  `Zend_Feed_Entry_Abstract`, `Zend_Gdata_App`, `Zend_Gdata_App_Base`,
  `Zend_Gdata_Gapps_ServiceException`, `Zend_Pdf_Filter_Compression_Flate`,
  `Zend_Search_Lucene_Storage_Directory_Filesystem`,
  `Zend_Search_Lucene_Storage_File_Filesystem`. The `track_errors`
  save/restore pairs around them are removed rather than ported, since the
  setting no longer exists.
- `version_compare(PHP_VERSION, '5.6', 'gte')` in `Zend_Xml_Security::isPhpFpm()`
  — `gte` is not a comparison operator PHP recognises, and PHP 8 turns the
  silently-wrong result into a `ValueError`. This one is **fatal on every XML
  parse** and the class-load smoke could never have caught it, because it only
  fires when the method runs. Now `'ge'`.

### Fixed — behaviour the engine no longer tolerates

- Ten `continue` statements targeting a `switch` (a warning since PHP 7.3)
  became `continue 2`. Two of these were genuine logic bugs rather than
  notices: in `Zend_Pdf_FileParser_Font_OpenType::_extractCmapData()`, `break`
  fell through to `$cmapType = $format`, marking a usable cmap subtable as
  unusable; in `Zend_Form::addElements()` and `addSubForms()` the existing
  `break` semantics were preserved exactly.
- 272 implicitly-nullable parameters across 147 files now use the explicit
  `?Type $x = null` form required from PHP 8.4. Applied with
  `tools/fix_nullable_params.py`, which only touches already-typed parameters
  and is idempotent.
- Eight optional parameters that preceded a required one (deprecated 8.0) were
  fixed in 5 files, in two different ways because the textbook fix is not
  always behaviour-preserving. Deleting the `= null` default makes the
  parameter genuinely required, which converts a clean catchable exception
  into a fatal `ArgumentCountError` on exactly the error path the default
  existed to report — so where the method already validates and throws, only
  the default was removed (`Zend_Pdf_Element_Reference::__construct()`,
  `Zend_Service_WindowsAzure_Storage_Queue::deleteMessage()`,
  `Zend_Service_WindowsAzure_Diagnostics_Manager::setConfigurationForRoleInstance()`).
  Where the signature is reflected over by `Zend_Service_Console_Command` and
  bound positionally from `@command-parameter-for` annotations, the optional
  parameters were reordered to the end instead, so every CLI parameter stays
  optional and every flag keeps working
  (`Deployment::createFromStorageCommand()`, `createFromLocalCommand()`,
  `Certificate::getCertificatePropertyCommand()`). Both help screens were
  rendered end to end afterwards to confirm the reflection model still builds
  and orders all thirteen parameters correctly.

### Fixed — argument-inspection semantics changed in PHP 7

- `Zend_Validate_File_Count::__construct()` was broken on any PHP 7+ runtime
  for its documented two-argument form. The constructor normalises `$options`
  to `array('max' => $options)` and *then* read `func_get_arg(0)`/`(1)`. Since
  PHP 7 those functions report the **current** value of a parameter rather than
  the value as passed, so `min` was set to `array('max' => '5')` instead of
  `'5'` and `setMin()` threw `Invalid options to validator provided`. The
  positional arguments are now snapshotted before the normalisation.
  `new Zend_Validate_File_Count('5', '10')` reports min/max `5`/`10` again.
- The other 41 `func_get_args()`/`func_get_arg()` sites were audited
  individually and needed no change. PHPCompatibility's
  `ArgumentFunctionsReportCurrentValue` rule flags any assignment to a
  parameter, so in this codebase it latches onto the `Zend_Config`
  normalisation or the `$options = func_get_args()` branch itself — neither of
  which can run before the call it is paired with. The genuinely safe shapes
  are: reassign `$options` to `func_get_args()` and `array_shift()` from index
  0 (index 0 is the same argument PHP 5/7 gave); read `func_get_arg(1)` on a
  parameter that is never reassigned; and the deliberate variadic
  passthroughs in the Soap/Json/XmlRpc servers, `Mail_Protocol_Imap`,
  `Search_Lucene`, `Session_Namespace`, `Ldap_Filter*`, `View_Abstract`,
  `View_Helper_*` and `Stdlib_CallbackHandler`. Note that
  `func_get_args()` returns only the arguments actually passed — it does not
  synthesise nulls for omitted defaults.

### Changed — components documented as unavailable

- `Zend_Test_PHPUnit_*` (26 classes) target PHPUnit 3.x, whose class names do
  not exist in the PHPUnit 10 this package ships. They are recorded as
  documented-unavailable rather than ported: PHPUnit 4 removed `evaluate()`,
  the `setNegate()` convention and `PHPUnit_Framework_ComparisonFailure`, so a
  port is a rewrite of all eleven versioned constraint classes plus
  `Exception.php`, not a shim. Two classes of genuine PHP 8 bug inside them
  *were* fixed, since they bite on PHPUnit 3 too:
  - Seven constraint classes read their extra assertion arguments out of
    `func_get_args()`. They now take `$variable` and `$extra` as named
    parameters, which is what the caller always meant and does not depend on
    argument-inspection semantics at all. This is a readability fix rather than
    a bug fix: every one of those switches read index 2 or 3, i.e. a parameter
    that was never reassigned, so the PHP 7 change to argument inspection could
    not reach them. The guards stay arity tests (`func_num_args()`), not null
    checks, because an explicitly-passed null is still an argument.
  - Six `fail($other, $description, Foo $cannot_be_used = NULL)` signatures are
    explicitly nullable for PHP 8.4.

  The guard behaviour was verified directly: a three-argument
  `ASSERT_HEADER_CONTAINS` call still raises its "both a header name and
  content to match are required" exception, and the single-argument assertion
  types are unaffected.
- The three mcrypt-dependent components now fail with an explicit exception
  instead of an undefined-function or undefined-constant fatal. mcrypt was
  removed from PHP in 7.2 and porting to openssl would change ciphertext, so
  the documented-unavailable stance is kept:
  - `Zend_Crypt_Math::randBytes()`'s `mcrypt_create_iv()` fallback was
    unreachable — it sat behind `function_exists('random_bytes')`, which every
    PHP 7+ build satisfies — and is deleted rather than ported.
  - `Zend_Service_ReCaptcha_MailHide`'s `ENCRYPTION_MODE` and
    `ENCRYPTION_CIPHER` constants were `MCRYPT_MODE_CBC` /
    `MCRYPT_RIJNDAEL_128`. Reading either on a build without mcrypt throws
    `Undefined constant`, so the class could not even be instantiated to reach
    its own `_requireMcrypt()` guard. They are now the literals `'cbc'` and
    `'rijndael-128'` — the values mcrypt used — so the guard is what fires.
  - `Zend_Filter_Encrypt_Mcrypt::setEncryption()` is public and had no extension
    check of its own; it now raises the same message as the constructor, naming
    `Zend_Filter_Encrypt_Openssl` as the alternative.

### Fixed — deprecations reported on every class load

- The four static accessors on `Zend_Search_Lucene_MultiSearcher`
  (`set`/`getDefaultSearchField()`, `set`/`getResultSetLimit()`) read
  `$this->_indices` from a `static` method. PHP 8 makes that a fatal
  ("Using `$this` when not in object context"); PHP 5/7 only noticed it and
  evaluated it to null, so `getDefaultSearchField()` and `getResultSetLimit()`
  always threw "Indices list is empty" and the two setters silently wrote to
  nothing. The methods must stay static — `Zend_Search_Lucene_Interface`
  declares them that way, and PHP refuses to widen a static method to an
  instance method — so the index list is now mirrored into a static property
  when `__construct()`/`addIndex()` receives it. **This is a deliberate
  behaviour change:** those four methods went from always-broken to working.
- Five classes implementing `Serializable` (deprecated 8.1) now also implement
  `__serialize()` and `__unserialize()`: `Zend_Http_UserAgent`,
  `Zend_Http_UserAgent_AbstractDevice`, `Zend_Stdlib_PriorityQueue`,
  `Zend_Stdlib_SplPriorityQueue` and `Zend_Paginator_SerializableLimitIterator`.
  The interface and the legacy `serialize()`/`unserialize()` pair are kept —
  dropping the interface would turn "this object no longer serializes" into a
  *successful* empty `O:` payload, and it is published API. Once the magic
  methods exist the engine stops emitting the deprecation and stops routing new
  payloads through `unserialize()`, which is the security-relevant half. Both
  files that had duplicate literal logic (spec array, drain loop, item restore)
  now share one private helper between the two forms so they cannot drift;
  payloads written by the previous release still unserialize correctly.
- 138 `case`/`default` statements across 38 files were terminated with a
  semicolon instead of a colon, deprecated in PHP 8.5. Fixed with
  `tools/fix_case_semicolons.py`, which only rewrites a label whose semicolon
  is the terminator — a `case 1: foo();` has its semicolon in the body and is
  left alone.
- 122 non-canonical casts across 53 files: `(integer)` → `(int)`,
  `(boolean)` → `(bool)`, `(double)` → `(float)`, `(binary)` → `(string)`.
  These are pure aliases — verified identical results across every PHP type
  and value combination before swapping.
- 8 `${var}` string interpolations in `Zend_Gdata` now use `{$var}`, the form
  PHP 8.2 requires. Two of them build a property name for `property_exists()`,
  so the output was confirmed byte-identical.

### Fixed — functions deprecated in PHP 8.2

- `utf8_encode()` and `utf8_decode()` are deprecated from PHP 8.2. All 11 sites
  across 7 files now use `mb_convert_encoding()` — `ext-mbstring` is already a
  hard requirement in `composer.json`, so this adds no new dependency.
  `utf8_encode()` is an exact replacement (verified against 3,262 fuzzed
  samples, zero differences). `utf8_decode()` is exact on well-formed UTF-8
  (20,000 samples, zero differences) but produces a different number of
  substitute characters on malformed input; the five such sites read an Azure
  configuration file that declares `encoding="utf-8"`, so malformed input is
  out of contract. The two S3 signing paths were re-run end to end and produce
  byte-identical HMAC signatures.

- `iconv_set_encoding()` with the `internal_encoding` / `input_encoding` /
  `output_encoding` type arguments is deprecated from PHP 5.6. All 11 sites
  across 5 files were already guarded by `PHP_VERSION_ID < 50600` with the
  `ini_set('default_charset', ...)` form in the `else` branch — so on PHP 8
  none of them had executed for years. The guard and the iconv branch are
  deleted, leaving the `ini_set` path that was already running. Pure dead-code
  removal, no behaviour change.

- `libxml_disable_entity_loader()` (deprecated 8.0) removed from
  `Zend_Xml_Security::scan()` and `Zend_Feed_Reader::getLinks()`. On PHP 8
  external entities are not resolved unless `LIBXML_NOENT` is passed, and
  `scan()` separately rejects any DOCTYPE that declares an entity — both were
  verified before the call was dropped, and both were re-verified after. The
  `libxml_use_internal_errors()` save/restore around it stays.
- `xml_set_object()` (deprecated 8.4) removed from the five XML translation
  adapters (Tmx, Xliff, Tbx, Qt, XmlTm). It existed only to tell the expat
  parser which `$this` the bare method-name handler strings referred to, so the
  handler registration now passes fully formed `array($this, '_handler')`
  callables and the call is unnecessary. All five adapters were re-run against
  the repository's own fixtures and parse the same message counts as before.
- `imagedestroy()` (deprecated 8.5) replaced with `unset()` in
  `Zend_Captcha_Image` and `Zend_Barcode_Renderer_Image`. Since PHP 8 GD images
  are `GdImage` objects freed by refcounting, so the call was already a no-op.

### Fixed — misleading XML error messages

- `Zend_Xml_Security::scan()` now reports the actual libxml parse error to
  callers that read `error_get_last()`. Previously the deprecated
  `libxml_disable_entity_loader()` call fired *after* the caller's
  `error_clear_last()` and its deprecation text became the "cause"; with that
  call gone the message went empty, because `scan()` parses into libxml's
  internal error buffer and never touched PHP's last-error slot. `scan()` now
  reads `libxml_get_last_error()` and re-raises it via
  `@trigger_error(..., E_USER_WARNING)` — recorded without being printed, so
  callers that raise their own exception do not also emit a stray warning.

### Added

- `tools/smoke.php` — class-load harness. Autoloads every class in `library/`
  in a forked subprocess and reports OK / MISSING / FATAL / DEPRECATION per
  class. This is the port's highest-signal regression check, because the
  upstream PHPUnit 3.x suite in `tests/` cannot run on PHP 8.
- `tools/port-status.sh` — regenerates the measured block in `PORTING.md`.
- `tools/fix_nullable_params.py` — the implicitly-nullable codemod.
- `tools/fix_case_semicolons.py` — the `case`-terminator codemod.
- `tools/fix_track_errors.py` — rewrites the `@ini_set('track_errors', 1)` /
  `@ini_restore('track_errors')` brackets in `Zend_Feed` and `Zend_Gdata_App` to
  `error_clear_last()` plus a hoisted `error_get_last()`. Idempotent.
- `PORTING.md` — resumable ledger: work queue, open decisions, known-benign
  smoke results, and the generated status block.

### Changed

- Package identity is `maheshk-cyber/nbh-zf1`, PHP `>=8.1`, with `ext-mbstring`
  and `ext-ctype` pinned as required. PSR-0 autoloading and the Composer
  `include-path` entry are retained so the ~7,700 `require_once 'Zend/...'`
  calls resolve without a manual `set_include_path()`.
- Dev toolchain moved to PHPUnit 10, Rector 2, PHPCS 4 and PHPCompatibility.

### Known unavailable

These cannot work on PHP 8 because the extension they need was removed from PHP
itself. The classes remain in the tree and are documented rather than fixed:

- `Zend_Crypt_Math`, `Zend_Service_ReCaptcha_MailHide` — `ext-mcrypt` (see the
  open decision in `PORTING.md`; a migration to openssl is possible but needs
  review)
- `Zend_Cache_Backend_Sqlite` — SQLite 2
- `Zend_Serializer_Adapter_Wddx` — `ext-wddx`
- `Zend_Db` `oci8`/`mysql_*` helpers, `Zend_Pdf` `track_errors` paths

`Zend_Test_PHPUnit_*` (26 classes) still targets PHPUnit 3.x APIs and is not
usable with the PHPUnit 10 that ships in `require-dev`.
