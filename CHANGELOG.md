# Changelog

All notable changes to this port are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[semantic versioning](https://semver.org/spec/v2.0.0.html) on the patched
upstream version.

Measured status — violation counts, smoke results, work queue — lives in
[`PORTING.md`](PORTING.md), which is regenerated by `tools/port-status.sh`.
This file records *what changed and why*; that file records *where we are*.

---

## [Unreleased]

Baseline: Zend Framework 1.12.20 (upstream EOL), retargeted at PHP 8.1+ and
verified syntax-clean through PHP 8.5.

### Fixed — fatal errors under PHP 8

- `Zend_Rest_Route::assemble()` gained the `$partial` parameter its parent
  `Zend_Controller_Router_Route_Module` declares. PHP 8 enforces this LSP rule
  at class-declaration time, so the class could not be loaded at all.
- `Zend_Soap_Client_Common::__doRequest()` now matches
  `SoapClient::__doRequest()`'s signature (`$oneWay = false`,
  `$uriParserClass = null`), which PHP 8 validates against the SPL class.
- `Zend_Service_WindowsAzure_Log_Writer_WindowsAzure` referenced three classes
  that do not exist in the tree — `Zend_Service_Log_Exception`,
  `Zend_Service_Log_Formatter_Interface` and
  `Zend_Service_Log_Writer_WindowsAzure`. Upstream escaped notice because the
  first two are only reached via `throw`; the third was a docblock typo. All
  three now point at their real `Zend_Log_*` counterparts.
- `Zend_Config_Yaml::_parseValue()` called `count()` on a string, which throws
  a `TypeError` on PHP 8. Now uses `strlen() - 1`.
- `Zend_XmlRpc_Value::_extractTypeAndValue()` could recurse forever on an empty
  `<value/>` element; the child-binding is now reset per attempt and falls
  through to the default string branch.

### Fixed — functions removed from PHP

- `each()` is gone from PHP 8. Replaced at four sites. `Zend_Config_Yaml` was
  the delicate one: it relied on `each()`'s internal array pointer together
  with `prev()` and recursion, so it now threads an explicit `$offset` cursor
  through `_decodeYaml()` instead of switching to `foreach`.
- `create_function()` (removed PHP 8) replaced with a closure in
  `Zend_Feed_Element::__get()`.
- `get_magic_quotes_gpc()` (removed PHP 5.4, but still called) — the guarded
  branch in `Zend_Tool_Project_Provider_DbAdapter` was dead code and is removed.

### Fixed — behaviour the engine no longer tolerates

- Ten `continue` statements targeting a `switch` (a warning since PHP 7.3)
  became `continue 2`. Two of these were genuine logic bugs rather than
  notices: in `Zend_Pdf_FileParser_Font_OpenType::_extractCmapData()`, `break`
  fell through to `$cmapType = $format`, marking a usable cmap subtable as
  unusable; in `Zend_Form::addElements()` and `addSubForms()` the existing
  `break` semantics were preserved exactly.
- 272 implicitly-nullable parameters across 147 files now use the explicit
  `?Type $x = null` form required from PHP 8.4. Applied with
  `tools/fix_nullable_params.py`, which only touches already-typed parameters
  and is idempotent.

### Fixed — deprecations reported on every class load

- 138 `case`/`default` statements across 38 files were terminated with a
  semicolon instead of a colon, deprecated in PHP 8.5. Fixed with
  `tools/fix_case_semicolons.py`, which only rewrites a label whose semicolon
  is the terminator — a `case 1: foo();` has its semicolon in the body and is
  left alone.
- 122 non-canonical casts across 53 files: `(integer)` → `(int)`,
  `(boolean)` → `(bool)`, `(double)` → `(float)`, `(binary)` → `(string)`.
  These are pure aliases — verified identical results across every PHP type
  and value combination before swapping.
- 8 `${var}` string interpolations in `Zend_Gdata` now use `{$var}`, the form
  PHP 8.2 requires. Two of them build a property name for `property_exists()`,
  so the output was confirmed byte-identical.

### Added

- `tools/smoke.php` — class-load harness. Autoloads every class in `library/`
  in a forked subprocess and reports OK / MISSING / FATAL / DEPRECATION per
  class. This is the port's highest-signal regression check, because the
  upstream PHPUnit 3.x suite in `tests/` cannot run on PHP 8.
- `tools/port-status.sh` — regenerates the measured block in `PORTING.md`.
- `tools/fix_nullable_params.py` — the implicitly-nullable codemod.
- `tools/fix_case_semicolons.py` — the `case`-terminator codemod.
- `PORTING.md` — resumable ledger: work queue, open decisions, known-benign
  smoke results, and the generated status block.

### Changed

- Package identity is `maheshk-cyber/nbh-zf1`, PHP `>=8.1`, with `ext-mbstring`
  and `ext-ctype` pinned as required. PSR-0 autoloading and the Composer
  `include-path` entry are retained so the ~7,700 `require_once 'Zend/...'`
  calls resolve without a manual `set_include_path()`.
- Dev toolchain moved to PHPUnit 10, Rector 2, PHPCS 4 and PHPCompatibility.

### Known unavailable

These cannot work on PHP 8 because the extension they need was removed from PHP
itself. The classes remain in the tree and are documented rather than fixed:

- `Zend_Crypt_Math`, `Zend_Service_ReCaptcha_MailHide` — `ext-mcrypt` (see the
  open decision in `PORTING.md`; a migration to openssl is possible but needs
  review)
- `Zend_Cache_Backend_Sqlite` — SQLite 2
- `Zend_Serializer_Adapter_Wddx` — `ext-wddx`
- `Zend_Db` `oci8`/`mysql_*` helpers, `Zend_Pdf` `track_errors` paths

`Zend_Test_PHPUnit_*` (26 classes) still targets PHPUnit 3.x APIs and is not
usable with the PHPUnit 10 that ships in `require-dev`.
